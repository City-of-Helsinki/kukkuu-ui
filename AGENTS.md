# Kukkuu Public UI Agent Instructions

## Role

You are working on `kukkuu-ui`, the public-facing web application for the Kukkuu platform, used by guardians to browse events and register children.

## Ecosystem

- **`kukkuu`**: The backend that provides the primary GraphQL API.
- **Headless CMS**: Provides dynamic content via `react-helsinki-headless-cms`.
  For the full architectural picture, see the [Service architecture](README.md#service-architecture) in the README and the backend's `ARCHITECTURE.md`.

## Commands

- **Install dependencies:** `pnpm install` (requires Node `>=24.15` and pnpm `11.9.0`).
- **Run dev server:** `pnpm start` (runs on port 3000).
- **Build:** `pnpm build`.
- **Lint & Format:** `pnpm lint`, `pnpm format:code`.
- **Typecheck:** `pnpm typecheck`.
- **Test (Unit/Integration):** `pnpm test` (uses Vitest, run with `TZ=Europe/Helsinki`).
- **Test (Browser):** `pnpm test:browser` (uses TestCafe, assumes the app is running on port 3001, see README for details).
- **Generate GraphQL Types:** `pnpm generate:graphql`.

## Environments & Data

- **Env files:** Uses `.env.development` (points to public test backend) or `.env.development.local` (for local backend, copy from `.env.development.local.example`). Key variables: `VITE_API_URI`, `VITE_CMS_URI`.
- **Data Fetching:**
  - Kukkuu API data is fetched via Apollo Client (GraphQL).
  - CMS content is fetched **only** via `@city-of-helsinki/react-helsinki-headless-cms`. Do not write raw WordPress fetches. Note that this library is shared with other projects; check for upstream changes before attempting workarounds.

## Domain Logic

- **Projects & Privileges**: A project groups children and events by birth year. Note that Admin UI manages projects, and access to them depends on user privileges.
- **Events & Event Groups**: Events are organized into event groups. An event group contains multiple events. Both an event group and an individual event always belong to a single project.
- **Enrollment Limits**:
  - A project's properties configure how many times a child can enrol per year (usually twice).
  - A child can participate in only **one** event within a single event group. For example, if only one event group is available for a spring season, the child can participate only once during that spring, as all available events belong to that one group.
- **Visibility Rules (Events vs Enrolments)**:
  - Published events and occurrences remain globally visible so the public UI and other event organizers can view them.
  - Unpublished events and occurrences are strictly isolated. Only system administrators and users who are members of the event's designated organisation can view or administer them.
  - Enrolment and attendee data are **never** globally visible, regardless of the event's publish state. Only system administrators and members of the event's organisation can access them.

## Rules and Guardrails

- **Generated Files:** `src/domain/api/generatedTypes/graphql.tsx` and `src/domain/headlessCms/graphql/__generated__.ts` are generated by `pnpm generate:graphql`. Never hand-edit them.
- **Commits:** Must follow Conventional Commits. Husky `commit-msg` runs `commitlint`.
- **Hooks:** Husky `pre-commit` runs `doctoc` and `lint-staged`.
- **Release Management:** The version, `CHANGELOG.md`, and `.release-please-manifest.json` are owned by `release-please`. Do not edit them.
- **Secrets:** Never read or commit `.env*.local` files.

## Cross-Repo Impact Checklist

If there has been a change in the backend's GraphQL schema:

1. Ensure the local backend is running with the new schema.
2. Run `pnpm generate:graphql` here.
3. Run `pnpm typecheck` and `pnpm test` to verify the frontend still works.
